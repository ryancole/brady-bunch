What it does

Stop juggling six terminals.

Describe your stack once in a brady.toml. From then on, one command brings it all up, and one click takes it all down.

Everything in one window

Console and GUI apps are embedded side by side in a grid. Click a tile to type into it; double-click its header to zoom.

Starts in the right order

An app can wait until another is listening on a port, answering HTTP, or has printed a line, with depends_on and ready.

Builds first

Tasks like dotnet build or npm ci run before anything starts. A failed build stays on screen; fix it and press Enter.

Shuts down gracefully

Closing the window sends each app Ctrl+C, in reverse dependency order, and only kills what's left after a timeout. Nothing is orphaned.

Scriptable

brady-ctl up returns once the stack is ready. Check status as JSON, restart one app, or rebuild while the rest keeps running.

Notices crashes

A crashed app's tile turns red and the taskbar flashes. Its console stays open with the last output. Restart it automatically, or with a keypress.

Configure

One small file.

A task, three apps, and the order they need. brady-ctl check validates it, down to whether every exe can be found.

  1. 1

    Build

    The build task runs to completion before any app starts.

  2. 2

    Wait for what you need

    api starts once db accepts connections on port 5432.

  3. 3

    Close to stop

    Apps get Ctrl+C one at a time, dependents first: api stops before db.

# brady.toml
title = "my stack"

[[task]]
name = "build"
command = 'dotnet build src\App.sln'

[[app]]
name = "db"
command = 'C:\tools\db\db.exe --port 5432'
ready = { tcp = 5432 }

[[app]]
name = "api"
command = 'dotnet run --no-build --project src\Api'
depends_on = ["db"]
ready = { http = "https://localhost:8002/health" }
exit_with = "main"

[[app]]
name = "web"
command = 'cmd /c npm start'
cwd = 'web'
PS> brady-ctl up
ready: build, db, api, web (12.3s)

PS> brady-ctl restart api; brady-ctl wait api
ready: db, api (3.1s)

PS> brady-ctl run build
build: done (8.4s); restarted api; ready (14.8s)

PS> brady-ctl tail api --lines 3
info: Microsoft.Hosting.Lifetime[14]
      Now listening on: https://localhost:8002
info: Application started.

PS> brady-ctl down
api: stopped by ctrl-c after 1834 ms
web: stopped by ctrl-c after 412 ms
db: stopped by ctrl-c after 96 ms

Control

Drive it from a script.

No more start-and-poll loops. brady-ctl waits for you and tells you what happened.

  1. ▶

    up / down

    Start the stack and return once it's ready, or stop it and return once it's gone. Exit code 4 and a reason if anything fails.

  2. ↻

    run build

    Rebuild while the stack runs: it stops the apps that lock the output, builds, and starts them again.

  3. { }

    status

    Every app's state as JSON, for tests, CI and coding agents.
